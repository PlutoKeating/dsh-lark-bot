# v0.19.11 — Channel health watchdog (half-open WebSocket self-heal)

- Fixes #108 (P0): a Feishu WebSocket could become **half-open** — the TCP socket stays `ESTABLISHED` and
  the bridge engine keeps writing a fresh heartbeat, but Feishu stops delivering events. `service status`,
  `doctor` and the guardian all reported healthy while inbound messages were silently dropped and no
  reconnect / guardian takeover happened.
- `bridge/channel`: now enables the SDK liveness `wsConfig.pingTimeout` (no inbound frame → the connection
  is judged dead and force-reconnected) plus the app-level `keepalive` watchdog (probes the connection and
  force-reconnects a stuck WebSocket). `onUnrecoverable` fires when even a forced reconnect fails: the
  engine logs it and **exits non-zero**, so the managed `service` / guardian restarts it on a fresh
  WebSocket generation (a new connection per event, so no stale generation leaks in).
- `ChannelHealthMonitor`: tracks the WebSocket lifecycle (`connecting | ready | reconnecting | failed |
  stopped`), connection generation, reconnect attempts, last inbound message and last reconnect, driven by
  the existing `message` / `reconnecting` / `reconnected` / `error` events plus a `getConnectionStatus` poll.
- The engine heartbeat now embeds a **channel-readiness snapshot** (backward compatible: readers ignore it
  when absent). `service status`, `doctor` and `guardian status` therefore distinguish **"engine process
  alive"** from **"Feishu channel ready"** (with generation / reconnect-attempt detail) instead of treating
  a fresh engine heartbeat as end-to-end healthy.
- Guardian observes "engine alive + channel not ready" and records a `channel-unhealthy` event, but
  **never preempts the channel** while the engine is alive (single-consumer fencing against double
  connection); it only takes over under the existing heartbeat-stale + no-dsh-process rule.
- New knobs: `DSH_LARK_CHANNEL_PING_TIMEOUT_SEC` (default 30), `DSH_LARK_CHANNEL_KEEPALIVE` (default 1),
  `DSH_LARK_CHANNEL_KEEPALIVE_MS` (default 15000), `DSH_LARK_CHANNEL_HEALTH_POLL_MS` (default 5000).
- Adds regression tests: `ChannelHealthMonitor` state/generation/inbound/error transitions, watchdog config
  forwarding, and heartbeat channel-snapshot round-trip.
- Verified against the full local test suite (144 files / 816 passed), typecheck, build, and the TUI
  admission (sha256:722ee4f6…), TUI PTY and publish-bundle gates.

Upgrade and reload the managed profile:

```bash
npx dsh-lark-bot@latest upgrade --profile dsh-lark --yes --restart
```

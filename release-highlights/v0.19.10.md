# v0.19.10 — Resilient npm-latest probe

- Fixes #110: `/version` (and the periodic update notifier) no longer keep reporting "最新版本查询暂不可用" for a full hour after a single transient registry blip. The bug was a combination of two mechanisms: the cheap single-attempt probe (`fetchNpmLatestVersionOnce`) had a tight 5s timeout that a cold `https://registry.npmjs.org/<pkg>/latest` response can cross (measured 4.0–5.0s cold on this network), and `latestVersion()` was negative-caching the resulting `undefined` for `UPDATE_CHECK_CACHE_MS` (1h).
- `update-check`: the in-memory cache now splits on outcome — a successful lookup keeps the full success window (1h), while a **failed** lookup is remembered for only 15s (`UPDATE_CHECK_FAILURE_CACHE_MS`), so the next `/version` re-probes instead of serving a stale failure. An explicit `cacheMs` override (e.g. `/new`'s `0`) is still honored literally so that path always re-probes.
- `versions`: `fetchNpmLatestVersionOnce`'s default timeout is raised 5s → 15s, aligned with the hardened path's `NPM_LATEST_TIMEOUT_MS`, so a single attempt survives the cold registry boundary without a multi-attempt worst case.
- Contrast preserved: the CLI `dsh-lark-bot upgrade` / `doctor` path already used the hardened `fetchNpmLatestVersion` (3 attempts + backoff + Accept-header fallback); `/version` was the fragile outlier and is now consistent with it.
- Adds regression tests: a failed lookup expires after the short failure window and is re-probed successfully, and an explicit `cacheMs` bypasses the failure cache.
- Verified against the full local test suite (146 files / 808 tests), typecheck, build, and the TUI admission/PTY and publish-bundle gates.

Upgrade and reload the managed profile:

```bash
npx dsh-lark-bot@latest upgrade --profile dsh-lark --yes --restart
```

# v0.19.1 — Runtime reliability fixes

- Keeps the explicitly configured dsh default model usable when the live model catalogue is unavailable during a cold start, without accepting unrelated unknown models.
- Repairs the authenticated policy-only approval callback so `ask`, `allow`, and `deny` reach SDK/Web runtime tools instead of being misreported as an unavailable bridge.
- Clarifies that Feishu/Lark slash commands are handled by the bridge separately from agent tools, with `/help` remaining authoritative when the runtime skill cannot be loaded.
- Marks completed turns containing failed tools as **Completed with warnings / 已完成（含警告）** in native and legacy process-card views while preserving the completed job outcome.

Upgrade and reload the managed profile:

```bash
npx dsh-lark-bot@latest upgrade --profile dsh-lark --yes --restart
```

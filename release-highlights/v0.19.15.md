# v0.19.15 — Real QR bind completion for WeChat / QQ (replaces stub polling)

- Replaces the placeholder device-flow poll with a **real implementation** so a
  scan actually completes the bind instead of always timing out to manual entry.
- **QQ (verified contract, mirrors NousResearch/hermes-agent `qqbot/onboard.py`)**:
  `create_bind_task` (locally generated AES-256-GCM key) → `poll_bind_result` →
  local decryption of `client_secret` → auto-produce the channel
  (`destination: user:<scanner openid>`, `secret: appId:clientSecret`). The QR
  target encodes the task id.
- **WeChat personal (iLink)**: `get_bot_qrcode` → `get_qrcode_status`. The
  scan-confirmed token/user field names are inferred from the community client and
  flagged for a live verification pass; `/channels accept` remains the manual
  fallback.
- `QqSink` now routes a `user:` destination to the C2C private-message endpoint
  (`/v2/users/{openid}/messages`) so a scanned QQ user receives notifications.
- Bind providers take an injectable key / fetch for testability; added unit tests
  for the QQ decrypt + completed/expired flow and the WeChat completed flow.

# v0.19.13 — Forward notifications to other IMs (Telegram / WeCom) as push-only sinks

- Adds #113: an optional, **outbound-only notification channel** abstraction. Feishu/Lark remains the
  single full-interaction platform; these channels only push and never accept commands, cards,
  questions, approvals or files. With no channel configured (and with `sinks` unset) behavior is
  identical to before.
- New `src/notify/sinks/` (mirrors the `AgentAdapter` seam): `OutboundSink` interface +
  `OutboundSinkRegistry` fan-out, `NotificationChannelStore` (`<profile>/notification-channels.json`,
  0600) holding `{ id, type, label, destination, secret, enabled, mentionMap? }`, and two stateless,
  official, push-only sinks — `TelegramSink` (Bot API `sendMessage`, `parse_mode=HTML`) and `WeComSink`
  (企业微信 group-robot webhook). Both are plain HTTPS POSTs with no third-party bot framework and a
  10s bound; a failing channel never blocks the others and never corrupts the Feishu terminal state.
- `NotificationPreference` gains `sinks: string[]` and a new `urgent` event. `NotificationDispatcher`
  keeps Feishu as the default first-class route and then fans out to the scope's selected channels;
  `notifyUrgent()` broadcasts crash / reconnect / heartbeat-anomaly fault classes to **every** enabled
  channel regardless of per-scope opt-in (and to Feishu when the scope opts into `urgent`).
- Credentials are stored at mode 0600 and rendered only through `maskSecret()` / `maskChannel()` — they
  never appear in logs, cards, `/channels`/`/status` output or the diagnostic bundle.
- Command surface: `/channels list|show|add|remove|enable|disable` (admin, e.g.
  `/channels add telegram Ops --destination @ops --secret <token>`), `/notifications … sinks=<id1,id2>`,
  and `/status` lists enabled channel ids.
- Wired reconnect/fault classes (`ReconnectNotifier`) through `notifyUrgent()` so a channel drop /
  reconnect / guardian heartbeat anomaly is mirrored to the configured sinks.
- Docs updated in both languages: README, ARCHITECTURE (key decision 18 + directory map), MANUAL,
  FEATURES, API, `.env.example`. Tests added for the channel store (0600), both sinks (mocked fetch),
  the registry fan-out/best-effort, the dispatcher urgent + sink paths, and preference normalization.

Verified against the full local suite (151 files / 846 passed), typecheck, and the build.

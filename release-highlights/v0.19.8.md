# v0.19.8 — Reliable resumption and version-safe rollback

- Fixes #104: `WebDshAdapter` now declares `resumeCapable = true` and an explicit `canResume`, so the run-flow gate reuses the native dsh session instead of creating a brand-new session for every Feishu message. The web server remains the single writer; unknown/expired ids fall back to a fresh session.
- Fixes #103: the managed SDK/ACP runtime overlay (`cordis.patch.yml`) is now regenerated from the installed (rolled-back) package's actual exported subpaths, so rolling back to an older version no longer leaves rows referencing subpaths that version does not export (`ERR_PACKAGE_PATH_NOT_EXPORTED`). `./sdk-server` falls back to the official SDK server when absent.
- Confirms the model-catalog refresh is non-blocking (5s timeout + stale-on-error + offline settings projection) and that `upgrade` verifies/repairs the pinned `@deepseek-ai/dsh-sdk-jsonrpc-server@0.1.0-rc.8` runtime dependencies.
- Adds rollback-compatibility tests for the SDK and ACP overlays, plus a network-independent catalog stub for the secret-target tests.
- Verified against the full local test suite (146 files / 804 tests), typecheck, build, and the TUI admission/PTY and publish-bundle gates.

Upgrade and reload the managed profile:

```bash
npx dsh-lark-bot@latest upgrade --profile dsh-lark --yes --restart
```
